# 交接包：工地安全「要不要通知」評測集（notify-eval-2026.01）

給 **LLM 課**（01 規則 baseline、07 凍結評測集、16／17 embedding 分類）使用。沒上過 ML 課也能用：你只需要 Python 3.10 以上，不需要 pandas、sklearn 或 GPU。

    python score.py                       # 檢查指紋、印出現有的成績表
    python score.py my-predictions.csv    # 把你的方法加進同一張表

## 題目

工地攝影機偵測到「疑似有人沒戴安全帽」時，會產生一筆事件。每一筆事件都要決定：**要不要通知現場安全主管（陳主任）？** 標籤 `needs_notify`：1＝要、0＝不用。標註規則見 `LABELING.md`。

## 檔案

| 檔案 | 內容 | 可以拿來做什麼 |
| --- | --- | --- |
| `eval-set.csv` | 977 筆事件（2025-12-29～2026-01-11），635 個 incident，150 筆要通知 | **只用來比較**，不用來調提示、挑門檻 |
| `eval-set.sha256` | `eval-set.csv` 的 SHA-256 指紋 | `score.py` 先比對；不符就拒絕評分 |
| `dev-sample.csv` | 40 筆（10 要通知），取自評測集**之前**兩週 | 寫提示、看例子、試錯 |
| `LABELING.md` | 標註規則、已知標註錯誤 | 判斷「答錯」是方法錯還是標籤錯 |
| `scores.csv` | 三個 baseline 在評測集上的成績 | 你的方法要贏誰 |
| `notify.yaml` | ML 模型的版本、門檻 0.2 與核准紀錄 | 知道 baseline 的成績是在什麼設定下量的 |
| `known-errors.csv` | ML 模型在評測集上答錯的 71 筆，含原因分類 | 看你的方法是不是錯在同樣的地方 |
| `manifest.json` | 版本、筆數、來源、使用規則 | 引用時寫 `dataset_version` 與 sha256 前 12 碼 |
| `score.py` | 評分程式（只用標準函式庫） | 同一把尺 |

## 欄位（`eval-set.csv`）

| 欄位 | 意思 |
| --- | --- |
| `event_id` | 事件編號，一列一筆 |
| `incident_id` | 同一件事被連續幾幀或兩支攝影機重複記錄時，共用同一個 incident |
| `confidence` | 偵測器覺得「沒戴」的信心（0.3～1）。**不是事實**，陰影、反光也會很高 |
| `duration_sec` | 追蹤器量到的持續秒數（誤差約 ±1.5 秒） |
| `light_lux` | 照度；夜班通常低於 300 |
| `people_nearby` | 畫面中附近的人數 |
| `tenure_days` | 這位工人的年資（天） |
| `prior_violations_30d` | 這位工人過去 30 天被認定要通知的次數（不含這次） |
| `hour`、`shift` | 幾點、哪一班（早班 6–14、中班 14–22、夜班 22–6） |
| `zone` | 區域：休息區、出入口、物料區、鋼筋區、高架作業區 |
| `site` | 工地 A～D |
| `needs_notify` | 標籤 |

## 成績怎麼比

- 主要看 **recall**（要通知的有沒有叫到）與 **cost**（10×漏報 + 1×誤報；漏報一次的代價＝誤報 10 次，陳主任訂的）。
- accuracy 會騙人：「全部不通知」的 accuracy 是 0.846。
- 每一筆都要回答。拒答或解析失敗請當成 1（交給人看），不要跳過，跳過的題目會讓分數虛高。
- 這份評測集**只能打開來比較**。依結果改提示，再用它量一次，量到的就不是「沒看過的資料」。要調整，用 `dev-sample.csv`。

## 注意

- 合成資料（`tools/build_data.py`，seed 20260112），不代表任何真實工地或人員。
- 這是**表格資料**，不是文字。LLM 要用，必須先把每一列轉成文字（例：「鋼筋區，持續 42 秒，信心 0.81，夜班……」）。轉法本身就是方法的一部分，要寫進報告。
